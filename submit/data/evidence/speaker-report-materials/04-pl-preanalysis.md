# 部分算法下放PL的事前分析

这是后续候选分析，未实施声纹网络PL加速器。目标是减少有效身份输出延迟并保持录音连续，不是单纯增加FPGA工作量。

| 候选 | 优先级与依据 |
|---|---|
| CAM++连续卷积/TDNN乘加块 | 优先用实际ARM逐算子记录确定热点，再评估整块下放；12个已量化卷积只是候选，MAC比例不等于耗时比例 |
| 48k→16k FIR与格式整理 | 适合作为小型流式前处理或配套；不能假设它足以解决整网延迟 |
| FFT/功率谱/Mel | opt1约10.912秒输入的Mel仅约0.219秒，暂不优先；现有定位FFT也不能直接给声纹用 |
| Silero VAD | 同输入约3.309秒，负担明显但含状态及另一种网络结构；首版留PS，必要时单独评估，音量门限不能等价替换 |
| 比较、阈值、登记、队列与有效期 | 运算量小或控制复杂，留PS便于迭代，保持故障和过期保护 |

建议使用一套可复用的卷积/乘加阵列，按层加载权重，连续块内尽量复用中间数据；不要给每层复制一套电路，也不要每层往返一次DMA。输入/权重可以评估8位，累加、偏置、缩放和饱和位宽须从范围推导并验证，不能直接截断。

历史PCM候选布线用量：LUT17398/53200、FF19351/106400、DSP41/220、BRAM36等价32/140，WNS+0.229ns。这是既有候选资料，不是本次新实现。剩余108块BRAM36按满容量仅486KiB；约685万参数即使全INT8也约6.53MiB，当前部分INT8还含浮点参数，因此权重需要DDR分块。剩余总资源不等于时序与布线余量。

现有音频DMA只有PL→DDR的S2MM，没有MM2S。加速网络需新增DDR输入/权重读通路、结果返回、缓存与仲裁，保证音频采集服务，并核算传输、CPU缓存维护、并发带宽、接口/控制资源和跨域。

32/64路MAC、100MHz下每路每周期1MAC的3.2/6.4GMAC/s仅为理想上限，不能当预计实测速率。收益预算应包括PS准备＋输入传输＋PL计算＋结果回传＋PS剩余计算；并发另看关键路径和资源争用。

进入实现前需要：热点及张量/量化参数、完整往返预算、定点数值对照；实现后分别取得仿真、资源、CDC/STA与板测证据。识别准确性与提速独立验收。参考[原始PL事前分析](https://github.com/TophBeifong1744/SoundSight/blob/0c5bfd5622a174a75c908c8a482983b098da8ecc/document/speaker-pl-offload-preanalysis.md)、[CAM++论文](https://arxiv.org/abs/2303.00332)、[ORT计时说明](https://onnxruntime.ai/docs/performance/tune-performance/profiling-tools.html)。
