## 3. 技术报告：按Word模板执行

### 3.1 封面与摘要

- 作品名称处注明：不要出现任何涉及学校名称等内容。技术报告应按此匿名要求整理，避免在正文或配图中不慎暴露学校信息。
- 摘要：**800字内**。

### 3.2 第一部分：作品概述

| 小节 | 模板限制与提示 |
|---|---|
| 功能与特性 | 400字内，可加重要图 |
| 应用领域 | 400字内，可加重要图 |
| 主要技术特点 | 400字内 |
| 主要性能指标 | 200字内，建议用表格 |
| 主要创新点 | 200字以内，逐点给出 |
| 设计流程 | 200字内，可加重要图 |

这些是各小节的独立限制，不是可以相互挪用的总字数额度。

### 3.3 第二部分：系统组成及功能说明

模板要求图文结合，阐述具体设计细节。

**整体介绍**

给出系统整体框图，标清各子模块，并说明模块之间的关系。

**硬件系统介绍**

- 硬件整体介绍。
- 机械设计介绍：如有机械结构，从总体到局部逐级展示，可采用CAD截图或手绘图。
- 电路各模块介绍：从总体到局部给出设计图，标记关键输入、输出信号；可采用电路图、SCH原理图或PCB版图等。

**软件系统介绍**

- 软件整体介绍，包含作品涉及的PC端或云端，结合关键图片；不为满足章节而虚构实际不存在的端。
- 软件各模块介绍：根据总体框图，从顶层到底层说明设计，提供相应函数流程图和关键输入、输出变量。

### 3.4 第三部分：完成情况及性能参数

模板要求展示最终实现成果，图文结合，**实物照片为主**。

- 整体介绍：整个系统的正面及斜45°全局照片。
- 工程成果：分别展示机械、电路和软件成果；机械、电路用实物照片，软件用界面照片。
- 特性成果：逐项展示功能、性能参数等量化指标，可加入重要仪器测试或现场照片。

### 3.5 第四部分：总结

- 可扩展之处：**300字内**。
- 心得体会：**1000字内**，可包含研发和制作细节。

### 3.6 第五部分：参考文献

- 按标准格式编排。
- **限20篇以内**。
- 当前提供的模板未注明具体文献格式标准编号，不自行补写为已经确定的赛方要求。

## 4. 设计报告：覆盖七类内容

以下直接对应“3.3.5.3 设计报告”截图：

| 内容 | 需要回答或展示什么 |
|---|---|
| 选题背景与创新点 | 为什么选这个题目；解决什么实际问题；前人做过什么 |
| 设计原理与功能框图 | 系统工作原理、功能组成和模块关系 |
| 软硬件划分依据与接口设计 | 为什么这样分工，以及各部分如何交换数据和控制信息 |
| 优化过程 | 包含优化前后的性能与资源对比表 |
| 大模型协作记录 | 提示词、模型回答、自我纠错轨迹、智能体工作流设计（如有） |
| 技能包的提炼过程 | 从哪些失败或观察中总结；如何验证有效；如何确定适用边界 |
| 复现说明 | 提供一份可由他人从零开始完整执行的操作步骤 |

截图未规定设计报告的总字数或各章字数，不把技术报告的字数限制直接套过来。

## 5. 设计报告：评分权重和写作重心

以下权重按用户提供的评分截图记录，**只用于本次设计报告，不套用于技术报告**。

| 评分项 | 分值 |
|---|---:|
| 创新性与应用价值 | 30 |
| 性能与资源优化效果 | 20 |
| 功能正确性与设计完整性 | 20 |
| 大模型协作与技能包 | 15 |
| 文档质量与可复现性 | 15 |
| 合计 | 100 |

**创新性与应用价值权重最高。** 设计报告应首先让评审理解：服务什么对象、解决什么问题、已有方法的不足在哪里，以及本设计作出了哪些有意义的改进。系统架构、技术实现与测试数据应支持这些论点，而不只是罗列模块和功能。

权重不等于篇幅比例；不能机械规定创新部分一定占全文30%。其余项目合计70分，也需要完整的证据和说明。

截图另有以下评审说明：

- 两组独立排名、独立评奖，应结合所属组别的考察侧重把握尺度。当前截图没有给出两组的名称，不在本文推断。
- 功能正确性与可复现性主要依据提交物核查和实测数据。
- 优化目标包括与基线的性能对比、合理使用片上资源，以及保证他人能够从零复现。

### 5.1 写作落实建议（不是额外赛事条款）

- 创新论证区分原有方法、第三方组件、本项目实现改进和系统协同设计，避免只靠更换术语制造创新点。
- 优化表说明输入、候选版本、运行平台、时钟/约束、测量范围和前后改动；不同条件的数字不能直接拼成加速倍数。
- 同时交代优化收益与代价，如吞吐、延迟、资源、存储、数据淘汰或识别效果之间的取舍。
- 大模型协作采用真实记录，展示提出建议、发现问题、修正与验证的关联，而不是只写“使用了AI”。
- 技能包说明可复用的方法、输入输出、验证及边界，而不是仅提供一个打包文件。
- 复现说明应补齐环境、依赖、配置、操作顺序、预期输出和常见异常处理，避免仅写“运行脚本即可”。

## 6. 中文与英文海报：按老师案例参考制作

### 6.1 案例体现的内容组织

参考PPT为一页横版，画布比例为16∶9。图片给出的分区含义如下：

| 位置 | 案例内容 |
|---|---|
| 顶部标题区域 | 作品标题 |
| 顶部信息区域 | 团队信息、学校名称/校徽、作品实物缩略图、测试平台信息 |
| 左侧 | 背景、关键内容摘要、应用场景 |
| 中部 | 系统框图、设计说明、关键创新点 |
| 右侧 | 测试结果、性能与展望 |

案例中的射电望远镜、高速采集板、学校与人员信息不属于SoundSight，制作时替换为本项目对应内容，不沿用其数据与结论。

### 6.2 版式与双语对应

- 参考案例的图文层次和阅读路径，采用系统图、实物图和结果图表帮助快速理解。
- 中文、英文版本的功能范围、数据口径、图表含义和结论保持一致；英文允许为自然表达调整句式和排版。
- PPT中示例标注了标题Times New Roman 24、团队姓名Times New Roman 12、正文Calibri 11。它们属于案例样式参考，当前没有依据将其认定为赛方强制字体字号，也不能直接推定中文字体要求。
- 现有案例未明确最终打印尺寸、出血、分辨率或必须交PDF等限制；正式制作或输出时以进一步提供的要求为准。

### 6.3 匿名要求不能跨材料混用

技术报告模板明确要求不出现学校信息，而海报案例预留了校名、校徽和成员姓名。两者适用场景不同：**技术报告执行匿名要求，海报是否展示身份信息须依据海报本身的提交要求确认。** 既不把技术报告的匿名要求自动扩大到全部海报，也不因为海报案例有校名就向技术报告加入校名。

## 7. 四份材料共同需要保持的关系

- 作品名称、系统架构、功能口径、主要术语和指标单位前后一致。
- 同一个实验在不同材料中的数据和条件一致，不能一处写离线测试、另一处写成实时板测。
- 实际完成状态、设计目标、测量结果与推断区分清楚；可复现材料与所引用的候选对应。
- 海报突出关键信息，报告保留论证细节；不因展示篇幅短就删除影响结论的重要条件。
- 文档质量与可复现性的落实，最终应能由提交文件和实际操作检验，而不是只凭文字自述。

这些是对材料一致性和评审证据要求的落实，不新增性能达标阈值或额外验收项目。

## 8. 不在本文冒充赛方要求的事项

以下内容已经在项目讨论中出现，但性质不同，应另列“项目范围/个人写作要求/内部核验清单”：

- SoundSight最终四项功能范围：RGB触摸屏交互、三维定位、声纹识别、双轴指向。这是2026-11-02更新后的项目方案，不是截图规定所有作品都要具备的功能；接合关系以[最终报告范围规则](final-report-scope.md)为准。
- 拓芙希望采用更正式、偏论文式的语言。这是个人表达偏好，不是模板明确指定的统一文风。
- 按最终成品状态先写内部预写稿、另列待核实事项。这是内部写作安排，不是赛事允许把未完成结果当成已验证成果的规定。
- 当前三项重点核验：触摸屏实际操作、不同人的声纹对照、三维方向与双轴实际指向。它们属于本项目证据缺口，不是赛方通用章节。

因此，本文不冻结拓芙之后提出的个人要求，也不表示两份报告或海报已经完成。后续写作以本文件为提交格式与评审关注点的依据，再叠加另行确认的个人要求和项目证据。
