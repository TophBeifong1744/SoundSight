## 下一步先查哪里

先核实垂直信号的实际输出，暂不靠扩大角度试错，也不因寄存器接受成功就盲改RTL。

若板子仍是115°试验后的状态、没有重启/重新加载，可以先做这项只读回读：

```sh
sudo env XILINX_XRT=/usr /usr/local/share/pynq-venv/bin/python3 -c "from pynq import MMIO; m=MMIO(0x40000000,4096); print('CAP=',hex(m.read(0xa0)),'STATE=',hex(m.read(0xa8)),'LAST_TARGET=',hex(m.read(0xc0)),'V_LIMITS=',hex(m.read(0xd0)),'FAULT=',hex(m.read(0x64)))"
```

在这个前提下，预期CAP为`0x44554101`，STATE为`0x200`，LAST_TARGET为`0x730000`，V_LIMITS为`0x730069`，FAULT为0。它只补充控制状态，不证明PWM到达舵机。

关键缺件是**手动命令有效期间，从W15对应输出到垂直舵机信号端的波形**。代码预期周期20ms，110°约1500µs，115°约1545µs；结束后输出低属正常，不能只在命令结束后测。没有波形、只有板端有波形、舵机端波形正确却不动，分别指向不同排查路径。目前没有证据确定是哪一种。
