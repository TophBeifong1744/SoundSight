# SoundSight：本次 FPGA RTL、模块与 BD 改动总结

【历史资料，2026-10-29状态更新】STM32路线已弃用；当前唯一主方案是Zynq-7020的PL＋PS/PYNQ。下文保留当时的设计、命令、分工及验证范围，不再作为当前派工或验收要求。当前入口以仓库README.md和document/main-architecture.md为准。

迁移说明：本文回顾10月17日RTL改动；正文旧目录名为历史位置。当前路径以本项目README及directory-guide.md为准。

日期：2026-10-17。对应当前名称含 `100MHz` 的迁移版本。

**这次改动的核心，是让 FPGA 只承担明确的采集、计算、缓存、通信和动作保护，把过宽的身份传递、重复诊断和协作核收机制移出运行通路，同时把最终方向求解交给 STM32 或 PS。**

本文用大白话解释“改了什么、为什么改、哪些不能删”，并单列后续可以继续改进的地方。它是当前代码与已有验证记录的整理，本次只新增说明文档，没有再次修改 RTL 或启动 Vivado 构建。

## 3. 哪些复杂机制去掉了，哪些仍然必须保留

### 3.1 去掉的是多余负担，不是把错误检查全部删掉

旧参考后端的 725 位身份由以下字段组成：

```text
token 64 位 + generation 64 位 + context 165 位 + frame_first 432 位
```

旧 6626 位前端终结记录还携带上述身份和大量原始审计信息。这些内容分布在数据、取消和终结接口上，会增加宽总线、比较器、寄存器，以及模块之间的控制依赖。

现在，计算链同一时刻只处理一帧，用真实窗口帧号贯穿 `begin`、谱点和 `end`。接收端仍检查帧号、通道、频点及数量是否正确。**把“这是谁发的、经过哪些层”简化成“这是哪一帧的哪一个数据，是否完整有效”。**

旧身份字段并不全是密码学意义的“防伪”；其中也混有真实的数据关联信息。改造方式是提取必需的含义，用更直接的信号表达，而不是删完后把检查结果接成常量“通过”。

当前新 RTL 运行通路没有源码哈希验证、cookie 核验或旧 725 位身份链。历史目录和说明中可能仍出现这些词，那是保留的旧代码或解释文字，不表示当前 BD 仍在实例化它们。

### 3.2 明确区分“放在电脑里”与“必须在硬件里”

| 内容 | 是否属于当前硬件必要功能 | 本次处理 |
|---|---|---|
| 源码 SHA、交付包哈希、聊天/任务编号 | 不属于声音定位运行所需数据 | 不进入 RTL，也不作为安装运行门槛；离线版本追溯可留在 Git/文档中 |
| 宽 token、generation、cookie 式身份核验 | 当前单帧计算链不需要这套层层证明方式 | 取消宽身份机制，改用明确的帧关联与状态 |
| 重复诊断银行、全量审计终结包 | 不需要每次运算都随链路携带 | 去掉旧框架，保留能定位故障的状态、计数及调试信号 |
| 真实窗口帧号 | 需要，避免把不同窗口的数据混在一起 | 保留 32 位真实帧号 |
| 公共快照序号 `FRAME_CNT` | 需要，识别新记录、丢帧和动作是否重复 | 保留；它不是内部窗口帧号的简单别名 |
| `valid/ready`、通道/频点顺序、末尾状态 | 需要，决定数据到底有没有收完、接住 | 保留并按真实握手处理 |
| `MAGIC`、`ABI_VERSION` | 需要正常设备识别和接口兼容检查 | 保留；不是防伪或加密协议 |
| 锁帧、消费、取消、超时、数值错误 | 需要，防覆盖、防错用和正常结束任务 | 保留，使用有明确含义的寄存器和状态 |
| 动作许可、看门狗、角度范围、STOP | 需要，直接影响输出行为 | 保留，并与计算/诊断长链分开 |

这里的 ABI 就是“FPGA 和 CPU 双方约好的寄存器、字段和操作规则”。SPI 和 AXI 也都是实际通信接口。需要简化的是多余包装和难以解释的规则，不能因为叫“协议”就一并删除。

**没有修改双方冻结的 SPI 字段、六对顺序、数值含义和阶段语义。** 两组代码仍按同一份合同通信，不能单方改几个位再让另一组猜。

## 4. 计算职责重新分配

### 4.1 FPGA 负责大量样本和确定的硬件动作

```text
四路 PDM 麦克风
  → CIC 抽取，得到四路 PCM
  → 分窗、复制当前窗口
  → 预处理与官方 FFT
  → 六对跨谱 / PHAT / 官方 IFFT
  → 整数相关峰及邻点
  → 六对整帧封存
  → 两槽快照
  → CPU 读取
```

PL 还负责寄存器通信、运行开关、必要故障状态、PWM 周期边界更新及动作保护。

### 4.2 STM32 或 PS 负责小规模求解和应用逻辑

CPU 接收每帧六对特征，完成亚采样插值、峰值可信度判断、有效对筛选、最小二乘求解、方位角计算和舵机坐标映射。旧 PL 后端中的 LS/角度求解路径及相应算术仲裁不再留在新六对引擎中。

这样做的原因是：原始音频数据量大，适合在 PL 连续处理；六对特征每帧只有 120 字节，CPU 处理和解释更方便，也更容易修改算法。

主方案使用 STM32 的 S1；独立 PS 版复用同一份 S1 C 算法，通过 AXI 寄存器读取特征。**独立 PS 版不再依赖 STM32，但仍需要正确的 PS 启动、DDR、软件环境和实机执行验证。**

主方案的 PS↔STM32 遥测/显示通道尚未冻结，不能把“后续展示职责”写成已有完整展示系统。

### 4.3 重构保持了哪些数值规则

| 项目 | 当前保留的规则 |
|---|---|
| 采样与分窗 | PDM 3.072 MHz，PCM 48 kHz，1024 点窗口，512 点步进 |
| 预处理 | PCM 为有符号 24 位；Hann 为 U18F17；使用最近偶数舍入 RNE，不随意截位近似 |
| FFT 数据 | 预处理输出 S29，FFT结果按原规则回到 S25；官方 FFT/IFFT 配置保留 |
| 两路预处理含义 | 原算法域0为去均值再乘Hann，域1为直接乘Hann；两者均保留检查，仅域1用于方向计算。这里的“域”不是两个时钟域 |
| 六对顺序 | `01、02、03、12、13、23` |
| lag 正负 | 跨谱为 `Xa × conj(Xb)`；例如 a 的脉冲在8、b在5，lag为 `+3` |
| 频点及门限 | bin 7～85；保留 `当前平方幅度 × 2500 ≥ 本对最大平方幅度` 的判断，不改成方便但不等价的近似 |
| 每对输出 | 5个32位字：`FEATURE_0、peak、left、right、second`；六对共30字、120字节 |
| 相关值 | 原 S25 相关结果符号扩展为 S32；不改变正负号和原精度 |
| 终态 | 成功、拒绝、数值错、协议错、取消、跳过分别表达；六对都结束才发布，结束不代表六对都成功 |

改架构不是降低精度或放宽服务要求。当前定向样例满足已有测试预算，但还没有所有输入的最坏耗时证明。

## 5. RTL 按实际功能分块

当前模块按“能说清一个职责、能单独验证”划分。层次封装只连接信号，不再每包一层就新增一套身份、诊断或控制权。

| 功能组 | 主要模块 | 大白话职责与边界 |
|---|---|---|
| BD入口与双时钟组合 | `bd_clean_compute`、`ss_dual_compute`、`ss_clean_compute` | 把计算链和跨域连接起来；BD入口是薄封装，不再实现一遍算法 |
| 麦克风采集 | `ss_pdm_capture`、`pdm_cic3` | 产生PDM时钟、采数据并抽取成四路PCM |
| 滑动窗口 | `ss_pcm_windows` | 管理连续样本和1024/512分窗，避免计算读取期间窗口被覆盖 |
| 预处理 | `ss_preprocess`、Hann系数文件 | 固定当前帧，完成均值/Hann和规定的定点舍入 |
| FFT调度 | `ss_fft_frontend`、`fft29_official` | 调度各通道与两种预处理输入，收完官方IP的数据和状态 |
| 六对相关计算 | `ss_pair_engine`、`doa_phat_client`、`doa_math_serial`、`doa_math_pkg`、`ifft25_official` | 六对串行完成跨谱、PHAT、IFFT和峰值提取；保留必要流水和多周期数值运算 |
| 六对整帧封存 | `f1a_frame_store` | 每对写入自己的位置，前一对不被后一对覆盖；完整帧才对外可见 |
| 跨时钟搬运 | `ss_async_word` | 用官方XPM异步FIFO整组传PCM或整帧结果，不逐位乱同步 |
| 公共快照 | `ss_snapshot_queue` | 两槽管理，区分空闲、可读、已锁；锁定内容不会被后台新帧改写 |
| SPI与寄存器 | `ss_spi_mode0`、`ss_control_regs`、`ss_stm32_link`、`bd_stm32_link` | SPI只负责读写事务，寄存器层统一解释命令、快照和故障 |
| 自检输入 | `ss_bist_source` | 提供可重复的通过/拒绝向量；自检不能触发实物动作 |
| 动作保护与PWM | `ss_actuator_control`、`motor_drive`、`i17_turntable_pwm_guard` | 检查许可和新鲜度，按周期更新PWM；停止时排完当前高脉冲，不再起下一脉冲 |
| PS版接合 | `ss_axi_lite_regs`、`ss_ps_control_regs`、`ss_ps_link`、`bd_ps_link` | 用片内AXI替代跨板SPI，接同一套计算、快照和动作保护职责 |

旧的 `ss_stm32_tile`、`bd_board_clock`、`ss_board_clock`、`sound_servo_clock` 保留作单时钟回归或参考，**不加入当前双时钟 BD**。不能因为源码目录里存在某文件，就认为它一定被综合到当前板顶中。

主要模块已补中文用途、接口和边界说明；完整参数与端口在现有模块目录/手册中。后续注释重点应是“为什么这样做、在哪一拍有效、停止后还欠什么”，而不是逐句把赋值语句翻译一遍。

## 6. BD 改成能看懂的两块业务逻辑加官方平台 IP

### 6.1 两种版本的主要连接

STM32主方案：

```text
四麦引脚 → compute：bd_clean_compute → link：bd_stm32_link ↔ STM32 SPI
                       ↑                    │
                       └── 运行使能 / ready ─┘
                                            └→ IRQ、受保护的舵机PWM

PS7 → 官方时钟/复位IP → compute、link
```

无STM32的PS版：

```text
四麦引脚 → compute：bd_clean_compute → ps_link：bd_ps_link → 舵机PWM
                                               ↑
PS7 M_AXI_GP0 → AXI Interconnect → AXI Clock Converter
                                               │
                         ps_link IRQ → PS IRQ_F2P[0]
```

PS版其余中断位接0。当前软件按状态/电平查询，不把BD中已经连IRQ等同于Linux中断驱动已经完成。

两版都引出真实平台所需的 DDR、FIXED_IO；具体 DDR/MIO/PYNQ 配置由 A 按实际板卡填写。脚本默认 PS 参数不是已经验证的板级 preset。

### 6.2 BD 中增加什么，不需要重复增加什么

| 类别 | 当前使用 |
|---|---|
| PS | `processing_system7` |
| 时钟 | 两级 `Clocking Wizard` |
| 复位 | 各业务时钟域的 `Processor System Reset`；配合官方XPM复位同步和必要逻辑 |
| 业务模块 | `bd_clean_compute` + `bd_stm32_link`；PS版将后者替换为 `bd_ps_link` |
| PS版总线 | AXI Interconnect、AXI Clock Converter、中断拼接 |
| 算法IP | 官方FFT/IFFT已在RTL内部实例化并由工程提供IP配置，不再往BD另塞第二套 |
| 数据跨域 | XPM FIFO和单比特同步器已在计算封装内部实现，外部同名接口不重复加CDC |

当前特征通路只有每帧120字节，不为这一用途额外建立DMA搬运链。以后若要传原始PCM或频谱，那是新的数据量和接口需求，需要另行设计。

### 6.3 计算块与通信块之间的实际接口

以下信号**全部属于61.44 MHz域**；内部100 MHz结果已经在计算块中跨域完成。

| 方向 | 端口 | 位宽 | 含义 |
|---|---|---:|---|
| compute → link | `feature_valid` | 1 | 当前有一帧待交接的结果 |
| compute → link | `feature_pairs` | 960 | 六对特征；每对160位，pair0在最低160位 |
| compute → link | `feature_flags` | 32 | 这帧的终态与必要标志 |
| compute → link | `source_faults` | 12 | 前端/计算侧故障状态 |
| compute → link | `draining` → `compute_draining` | 1 | 停止后还有任务或结果正在排尾 |
| link → compute | `feature_ready` | 1 | 接口层可以处理这次发布尝试 |
| link → compute | `run_enable` → `enable` | 1 | 允许计算链继续接受新工作 |

在当前双槽合同下，`feature_ready` 为1表示通信层会处理发布，包括“满槽时丢新并记账”；它**不是**“CPU已经保存了这一帧”的确认。不能混淆这两层含义。

### 6.4 时钟：保持采样参数，单独提高计算频率

```text
PS7 FCLK_CLK0：100 MHz
       │
       ▼
Clocking Wizard：clk_main
       ├── 100 MHz → 计算、PS侧AXI
       └── 96 MHz → Clocking Wizard：clk_audio
                                └── 61.44 MHz → 采集、SPI、快照、PWM、寄存器端
```

96 MHz只是生成精确61.44 MHz的中间时钟，不挂一套业务模块。当前不使用外部PL `sys_clk/U18` 作为主时钟入口。

公共 `WATCHDOG_TICKS` 的单位仍是61.44 MHz周期；PDM、PCM、PWM和冻结ABI没有跟着计算域一起改成100 MHz。主方案仍依赖PS先提供FCLK，并不是STM32供电后FPGA就自动有时钟。

### 6.5 复位：每个业务时钟域有自己的复位IP

| 用途 | 当前处理 | 会不会清已存快照 |
|---|---|---|
| 普通STOP | 停接新角度和任务，排尾；不把它当整片复位 | 不清 |
| PS普通总线恢复 | `FCLK_RESET0_N` 经100 MHz和61.44 MHz各自的总线复位IP | 在FCLK和PL配置仍存在的前提下保留 |
| 平台冷复位 | `FCLK_RESET1_N` 控制平台时钟/核心复位 | 清状态、清旧记录 |
| 失锁/失钟后的恢复 | 复位保护先断言；恢复需明确冷复位过程，不能只重新打开FCLK | 按冷恢复处理，不承诺保帧 |

`Processor System Reset` 的 `slowest_sync_clk` 接它服务的本域时钟，复位极性与常量电平按实际配置连接。BD自动连线可以完成基础结构，但不会自动理解本项目“总线复位保记录”的含义。

本次官方IP模型测试发现：目标时钟已经停掉时，仅靠原复位连接可能来不及更新输出。因此当前用 `locked` 与复位输出组合，再接官方XPM异步复位同步器，做到**失锁时可以不等目标时钟就进入复位，解除时在本域经过3拍同步**。两个业务域各一份。这项新增逻辑有实际故障场景依据，不是额外的身份核验框架。

## 7. 缓存、背压、取消和STOP怎么简化而不弄坏

### 7.1 两种缓存解决两种问题

| 缓存 | 当前规模 | 解决什么问题 |
|---|---|---|
| PCM跨域FIFO | 97位，16项：四路S24共96位加1位削顶标志 | 把同一组四通道采样从61.44 MHz整体交给100 MHz域 |
| 整帧结果跨域FIFO | 992位：960位特征加32位标志；逻辑仅允许1项在途 | 把整帧结果完整交回控制域；底层XPM物理深度16不等于16个公共快照槽 |
| 六对工作槽 | 一帧中的六个独立位置 | 逐对采入，直到六对都有终态再公开 |
| 公共快照 | 2槽，FREE/READY/LOCKED | CPU读取时保持整帧不变，明确谁能释放或消费 |

物理PDM不能被软件背压暂停。PCM缓存满会报错并停止启动新窗口；公共快照满则按冻结合同保旧丢新，记录gap/drop。没有“CPU慢多久都不丢”的承诺。

`ACQUIRE` 锁最老帧；重复获取仍是同一锁帧；`RELEASE` 只是退回可读；`CONSUME` 才删除。消费和新帧同拍时先释放槽，再接新帧，避免制造不必要的溢出。

内部窗口帧号标识音频窗口；公共快照序号在每次发布尝试时增长，丢新帧也计数。两者职责不同，不能为了少一个字段就混用。

### 7.2 STOP不再等整条计算链批准

STOP在控制域收到后，立即禁止接受新角度、禁止启动新的PWM脉冲。已经开始的高脉冲按既定规则完整结束；**“立即停止接新工作”不等于“无条件截断当前PWM高脉冲”**。

停止请求跨到计算域后，停止启动新FFT/IFFT任务；已经进入官方IP的事务继续收完必要输入、输出与status，再给出取消终态。不能靠随手清空状态机，让IP内部还欠着半个事务。

`draining` 覆盖停止同步往返、计算活动和在途结果，避免刚按STOP就把“还有东西没交完”误判为空闲。普通STOP不复位异步FIFO，也不删除已保存记录。

### 7.3 动作保护保留最直接的检查

PL继续检查独立动作许可、锁帧、新鲜度、水平角有效、机械范围、非零看门狗和故障。相同帧只能成功提交一次；只有新且被接受的命令才能续看门狗；BIST不允许实际动作。

PWM角度仍在周期边界更新。默认 `ACTUATOR_BOUND=0`，代码中的0～180默认范围不等于实际舵机零点、方向和机构限位已标定。冷复位立即撤输出，与普通STOP排完当前脉冲的语义不同。

## 8. 本次一起落实的其他改进

| 改进 | 实际意义 |
|---|---|
| 跨域用官方FIFO/同步器 | 多位数据整组搬运；独立状态位才做单比特同步，避免把不同时间的数据拼成一帧 |
| 保留数值流水与多周期运算 | 删除的是重复控制依赖，不把原先分拍的乘法、平方、PHAT又挤回一个周期 |
| 调试信号按时钟域区分 | frontend/backend状态属于100 MHz，通信/故障状态属于61.44 MHz；ILA采样时钟要匹配 |
| 实际错误能被看到 | 保留取消、数值错、格式错、满槽和计数状态；错误不会被统一包装成“已完成/通过” |
| PS地址来自实际HWH | 当前一次BD分配是 `0x40000000`、4 KiB，但应用读取实际HWH，不把这个地址当永久协议 |
| PS应用先保存再消费 | 写JSONL并完成`fsync`后才消费硬件槽；异常、退出和存储失败请求STOP，未保存帧保留 |
| 明确单一控制者 | STM32版由STM32独占；PS版由单一应用持有控制权，不增加两个同时抢帧的入口 |
| 脚本职责分开 | `prepare_bd.tcl`建立独立BD；`generate_outputs.tcl`生成IP/BD输出；报告入口只导出人工完成run后的结果 |
| 报告看真实范围 | setup/hold、未约束路径、CDC、DRC、资源和I/O都要看，不只看一个WNS或“命令退出0” |
| 资料集中、入口明确 | 当前100MHz包与保留的旧单域包区分；模块端口、算法、IP配置、BD接线可直接查 |

I/O约束中的路径预算是设计要求，不是实测结果。本次没有用整域false path、虚假的多周期、降低数值精度等手段把违例藏起来。

## 9. 还可以怎样改进——以下是建议，不冒充已经完成

这些建议不改变当前冻结接口，也不构成本次新增的强制流程。应先根据实际问题选择，不能再为了“完整”叠一套新框架。

| 优先考虑的改进 | 原因与建议做法 | 边界 |
|---|---|---|
| 先取得当前候选的物理报告 | 100MHz代码和BD能生成，不代表布线后的最长路径达标；用真实报告决定还要在哪处分拍或复制局部控制 | 综合/实现由A操作，本文不启动 |
| 优先核实PDM采样相位余量 | 当前接口预算留给setup、抖动和模型误差的余量约2.208ns，比较紧；需结合实际I/O路径与波形判断是否调整采样相位/结构 | 这是现有预算推导，不是板上测量；不能直接放宽约束 |
| 两版共享一份公共RTL维护源 | 当前两版各带可独立使用的公共文件，修改时容易只改一边；后续可用一个公共源码目录、两份目标文件列表，交付时再复制展开 | 不引入哈希验收门槛，也不让用户必须安装复杂发布系统 |
| 把遗留入口从“常用视图”移开 | 已经不参与当前BD的旧tile/clock容易让人误选；文件列表和说明始终只指当前入口，必要时把参考件单列 | 保留历史代码和失败证据，不直接删除 |
| 更清楚地命名内部状态和位域 | 固定ABI保持不变；内部可逐步用有名称的常量、局部结构和状态图替代散落位切片，注释“在哪一拍更新/谁能消费” | 不给外部协议再包一层新的票据或身份体系 |
| 继续压缩重复的故障判断 | 检查尽量放在真正拥有数据的模块边界；下游使用已寄存的结果，不每层重新解码整份数据 | 新事务、跨域和不可逆动作边界的检查仍需保留 |
| 明确所有副本的文档状态 | 例如早期接线说明的“尚未安装XDC”与后续独立BD已加入约束，是不同时间/对象；后续统一写明“旧实际工程/新独立BD/实板” | 不把过时文字当当前状态，也不为此恢复任务数据库 |
| 算法裁剪先有数值依据 | 当前域0检查和域1方向链都保留；若未来确认某一路可删，应先说明接受条件并做等价/误差验证 | 本次没有擅自删除域0、改精度或改S1 |
| 诊断按需提供 | 现有状态、计数和有限ILA先解决实际故障；若需要PCM/频谱，再增加独立可关闭的诊断通道 | 不恢复每帧巨型审计包，也不把诊断作为正常运算的前置依赖 |

完成上板功能还要补真实平台启动、STM32 S2或PS实机软件、引脚电气、真实声源定位和机械标定。它们是尚未完成的功能验证，不是“已经验证过、只差接几根线”。

## 11. 后续修改时沿用的简单原则

1. **每一个硬件字段都说得出实际用途。** 它是在标识音频帧、判断数据有效、保护缓存，还是控制输出？如果只是证明某个AI交付过，就放在电脑上的记录里。
2. **一个模块拥有一种明确状态。** 谁保存帧，谁决定能否覆盖；谁驱动PWM，谁落实停止。不要每层都复制一套许可和身份判断。
3. **停止、排尾、保存、复位分别表达。** 不用一个“大清空”同时代替四件事，也不让立即撤销新增动作等待长计算完成。
4. **跨域交整组数据，复杂运算按拍完成。** 简洁不是少写几个寄存器，而是让数据在什么时候有效、谁接收、何时完成一眼能看懂。
5. **注释解释设计原因和边界。** 写清单位、符号、时钟域、握手、失败路径；避免只有“证据、身份、候选”而没有实际物理含义的命名。
6. **用实际输入和结果证明功能。** 文件校验、BD通过、仿真通过、实现时序通过和板测通过分别表述，不能相互替代。
