# D4：纯软件双轴目标映射

D4已完成独立C99模块及PC测试，AC5对象编译通过。没有加入板端运行路径、修改SPI字段或生成双轴设备命令。二维默认、原S1/S2、Keil工程与所有动作门禁不变。

源码：[doa_target_3d.h](../common/s1_3d/doa_target_3d.h)、[doa_target_3d.c](../common/s1_3d/doa_target_3d.c)。

## 使用方式

输入为实际 `doa3d_solve` 返回状态和 `doa3d_output_t`，不重新求解方向。示例配置只描述数学模型，不是实物标定，默认 `enable_mapping=0`。

```c
doa_target3d_config_t config;
doa_target3d_output_t target;
doa_target3d_example_config(&config); /* 数学示例，默认关闭 */
config.enable_mapping = 1U;          /* 只打开数学映射，不是设备arm */
doa_target3d_status_t status = doa_target3d_map(solve_status, &solved,
                                               &config, &target);
if (status == DOA_TARGET3D_OK && target.software_target_valid) {
    /* 仅供离线显示/验证；不能把此输出交给现有P2补发动作。 */
}
```

返回保存输入 `frame_id` 和配置 `revision`，便于关联；它们不证明新鲜度、LOCKED槽、消费状态或设备许可。调用是无状态纯函数，无SPI、HAL、时钟、动态分配或历史目标缓存。输出与输入不可重叠。

本批未改Keil源列表；未来需要接入时，加入新C文件并继续链接原S1的 `doa_solver.c`，再与设备动作链一并验证。当前对象通过不等于已链接三维固件；本机Lite容量限制仍保留。

## 配置与公式

两个轴分别复用冻结 `doa_servo_config_t`，计算仍调用原 `doa_map_angle_q8`：

```text
mapped_q8 = offset_q8 + direction * angle_q8
先检查未舍入的mapped_q8是否处于机械范围
target_deg = RNE(mapped_q8 / 256)
```

|字段|要求|
|---|---|
|revision|非零uint32；零点、方向或限位改变时维护新修订号|
|enable_mapping|0默认关闭；1才可生成软件目标，不代表任何运动许可|
|两轴config_valid|必须为1，表示调用者明确提供配置，不表示程序完成了标定|
|offset_q8|零方向对应的目标角，Q8；沿用原有范围[-8388608,8388607]|
|direction|+1或-1，每轴独立；目前1:1角度比例|
|horizontal.domain_min/max_q8|有效方位域，必须在[-180°,180°)内，min≤max|
|vertical.domain_min/max_q8|有效俯仰域，必须在[-90°,90°]内，min≤max|
|mechanical_min/max|整数目标角限位，min≤max≤servo_max|
|servo_max|1～511，沿用旧数值映射约束，不表示新PL双轴线格式已确定|

示例两轴零点90°、正方向+1、输入[-90°,90°]、输出[0°,180°]。真实机构的零点/正反、限位和使用域要实测。结构合法不保证所有输入角都落入机械限位，运行时逐轴检查。

模型假定阵列坐标与理想正交yaw/pitch机构对齐。任意安装旋转、连杆非线性、减速比例、轴间碰撞约束，不能仅靠此处两个零点偏置处理，实物存在这些条件时应先补变换/标定。未实现速度/加速度限制、去抖、回差或轨迹规划。

## 无效目标处理

检查顺序为参数→映射启用→配置合法→原求解API成功→方向有效且无来源错误→两轴可观测→角度规范域→两轴映射/限位。

- 必须两轴都通过才设置 `software_target_valid=1`；任一轴失败，水平和垂直目标均清零，清零不是“执行0°命令”。无效时不得使用目标字段。
- 正上/正下方原求解器的 `azimuth_valid=0`，两轴目标无效。没有擅自保持上次水平角或只动垂直轴；若后续需要这种策略，须结合机构和运行状态另行确认。
- 不钳位超界值、不把+180°悄悄绕到-180°、不自动选择最短机械路径。方位域是一个不跨规范边界的闭区间，+180°输入本身非法。
- 先做机械限位再RNE：例如180°加1/256°不能因四舍五入回180°而通过。
- `axes_evaluated=0`表示尚未调用逐轴映射，两个逐轴状态初始化为DISABLED；需优先解释总状态。若为1，可检查horizontal_status/vertical_status定位超域或机械拒绝。单轴状态OK仍不代表整组可用。
- 本模块没有新鲜度检查、帧重放限制、设备许可、看门狗、STOP、动作ACK或双轴原子提交；这些仍属于之后的设备接合。不能把已消费帧的离线目标用于延迟补交命令。

## 实际PC输出

|输入／配置|预期|实测|
|---|---|---|
|方位45°、俯仰30°，双零点90°|135°/120°|135/120，有效|
|方位-45°、俯仰-30°|45°/60°|45/60，有效|

实测共92270项断言、0失败，其中92162组覆盖两种方向下完整[-90°,90°]的每一个Q8子角度；独立浮点参考检查两轴结果。另有16种坏配置、来源错误、极值、NULL、清旧目标与实际C求解器→双轴映射接合。AC5 C99严格对象编译0错误；本批没有新固件链接或板测。
