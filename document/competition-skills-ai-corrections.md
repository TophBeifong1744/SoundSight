# 用户可见的 AI 协作与纠错记录

本记录只整理可见请求、代码问题和实际验证，不收录隐藏推理，也不虚构旧聊天原文。

| 请求/观察 | 实际处理 | 结果与边界 |
|---|---|---|
| 用户询问“我们比赛里面要求的两个skills开发的怎么样了” | 读取当前 Skill、历史限定复核原件和示例依赖 | 确认已有真实模块仿真/离线成果，同时发现新仓库迁移未收尾；没有把历史批准说成当前交付完成 |
| 当前 PCM case 仍指向旧 rtl/acquisition 路径 | 先跑原单测，真实复现 FileNotFoundError；从保存的 examples-r2 实际输入恢复 C 的原模块 | 原字节带来源、许可证保留于自包含示例；不修改当前生产 RTL，不凭空重写模块 |
| 用户授权“适配到新仓库，修好路径和缺失依赖，统一说明并完成离线测试和必要的XSim验证” | 更新当前路径、说明和状态；保留旧证据原文；执行 Python 回归与真实 XSim | 仓库内 PCM792、elastic13800、三种故障检出、恢复后13800；PYNQ55测试/57子测试通过 |
| 用户明确“PYNQ实板部分先保留待办，不安排我上板” | 保留拒绝运行的板端入口，验证它不产生硬件报告 | 未连接板卡、未下载、未复位；真实适配器及板测仍 NOT_RUN |
| 旧说明同时存在“已批准”“待审”和旧版本数字 | 分开历史准确版本、本次迁移版与实际复跑报告 | 不覆盖原历史报告，不冒充 B/C 新批准，不用 Git 合并代表功能验收 |
| 用户要求比赛交付包 | 交付包内包含源码、测试、合同、许可证、本次输入与失败/复测结果；在脱离仓库的目录复跑 | 导出包的实际复跑结论以配套 package-check.json 为准，不只以 ZIP 创建成功判断 |

历史经验（不是本次新发现）：elastic 仅比较输出顺序会漏掉额外流水级；现有 TB 已增加每拍延迟/容量检查。DMA 曾有 HWH 实例误判、重复 ID 覆盖失败及大整数比较误差；原回归继续保留。这些不是用本次简单路径修改重新冒领的算法成果。
