# 2026-10-30 声纹与双轴板测、有效期建议

结论：声纹有效期先保持 **10秒**。两轮均正常结束，用户确认舵机有跟随；这是现场功能验证，尚不能代表身份识别准确率或所有场景长稳完成。

## 为什么选10秒

只用STOP之前的12次推理估计正常运行耗时：平均3.351秒，最长3.562秒。工程上暂按“相邻通过结果之间容忍一次未过线计算、另留20%余量、向上取整到2秒档”估算：

`2 × 3.5624 × 1.2 = 8.5498秒 → 10秒`

这个余量是明确的工程假设，不是由两轮小样本证明的统计置信界；语音窗口需持续可用，停顿、调度延迟和连续低分都可能超过10秒。第一轮两个通过结果实际相隔15.681秒，中间三次低分；10秒许可会自然到期约5.681秒，不建议为掩盖连续拒绝而直接改20秒。

通过分数每次从**完成时刻**刷新TTL。低分、换语音段和静音不提前撤销已有许可；超时且无新通过才失效，STOP或采集/处理故障立即撤销。当前方向的音量、角度筛选、限位仍独立生效。许可可能来自数秒前的声音，因此旧许可有效期内另一个声源可能获得方向跟随；延长TTL会放大这个范围。

`0.45`是当前试验门限，不是已标定结论；没有其他人对照，不能根据这两轮判断误识率。先保持TTL10秒，再采目标本人和其他人评分对照。

## 为什么统计次数不等于动作许可次数

第一轮有两次推理在STOP后收尾完成，第二轮有一次。累计统计按用户要求计所有成功数值计算（包含收尾），但不能当作运行期间许可刷新；本分析将它们排除于运行耗时预算。没有修改已保存的原始统计。

## 复算与使用

从仓库根目录：

```sh
python tools/analyze_speaker_sessions.py document/evidence/speaker-dual-axis-20261030/board-tests.zip --output document/evidence/speaker-dual-axis-20261030/analysis.json
```

板端停止当前会话后设置，下一会话生效，不直接转动：

```sh
sudo sh soundsight-3d.sh speaker-config --ttl 10
sudo sh soundsight-3d.sh speaker-check
sudo sh soundsight-3d.sh speaker-stats
```

继续带累计统计的联合运行需用户主动执行：

```sh
sudo sh soundsight-3d.sh speaker --axes both --seconds 0 --speaker-stats
```

Ctrl+C结束后保存本轮时间戳报告，短命令显示最近一次统计；历史报告不因更新最近统计而删除。当前测试参数：音量12000、窗口3帧/至少1帧合格、水平0～360、垂直0～220、目标user2。上述记录不自动替换个人配置。

完整计算见 [analysis.json](analysis.json)，本次源码和发布说明见 [集成说明](../../release-20261030.md)。
