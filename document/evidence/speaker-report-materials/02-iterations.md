# 迭代过程与实验结果

## 迭代主线

| 阶段 | 问题与取舍 | 结果及边界 |
|---|---|---|
| 方案/PCM | 先单人发声识别；从定位重叠窗之前导出连续PCM；复用原控制保护 | 后续938/1024包记录验证传输，但单次通过不是长期稳定 |
| ECAPA核心 | 先确认32位ARM能正确执行模型 | 3.104秒源语音特征，平均推理9.0638165秒；不含录音/前端，速度不足，见[E01](records/E01/serial-user.log) |
| CAM++ | 换轻模型并比较单/双线程 | 双线程3.164664秒、单线程5.8305275秒；同源语音但模型前端帧数311/308不同，不是完全相同张量，见[E02](records/E02/serial-user-threads2.log) |
| 图优化与部分INT8 | 比较动态/固定形状和12个前端卷积量化 | fp32-opt3.204435秒，fixed3.060105秒，int8-head2.796945秒；全部为核心、每组2次，见[E03](records/E03/serial-user.log) |
| 完整文件链路 | 核心测速不含PCM转换、VAD和Mel，需拆分计时 | Python转换曾占约4.5秒，转C后显著下降；不能把核心接近实时等同整链路实时 |
| 短窗口 | 评估0.5/1/1.5/2秒，减少每次计算 | 短窗更快但本人匹配变差；0.5秒在FP32和部分INT8均出现误拒，见[E04](records/E04/summary.json) |
| 连续缓存与rx1/2/3 | 避免重复前处理、队列积压与采集线程被计算拖住 | 最新候选覆盖旧待算任务、独立采集解释器、32包总信用；rx1/rx2成功和失败都保留，不称根治溢出 |
| opt1 | 每帧功率谱只算一次；跳过零Mel权重；复用缓存并合并CMN+推理请求 | 同两段10.912秒处理输入，前端7.333079→4.359630秒，减少40.55%；声纹步骤1.084741→1.082970秒，基本不变，见[E05](records/E05/board-opt1-bench.json) |
| epoch26实麦 | 检查单人正常音量真实并发 | 938包完整，三次分数/时效未形成有效身份；不能用离线优化代替实麦结论，见[E06](records/E06/board-epoch26.json) |
| CPU对照 | 区分网络执行与并发负担 | 独立1.089011秒、前端并发1.596941秒；增加46.64%，CPU量增加19.35%；等待字段不可读，见[E07](records/E07/board-profile.json) |
| 全链路/网络计时 | 进一步定位采集、前端、网络及发布延迟 | 增加ORT节点和模块记录、正常退出保存、逐Run完整性检查；该候选仅软件/ARM模拟/回放验证，不能作板端热点结论，见[E08](records/E08/tests.json) |

## 可以画哪些图

使用[metrics.csv](metrics.csv)，按comparison_group分图，保留scope与timing_boundary：

1. 核心模型/线程柱状图：ECAPA、CAM++单/双线程，源语音同为3.104秒，注明不同模型特征帧数及每组仅2次。
2. CAM++候选柱状图：fp32-opt、fp32-fixed、int8-head，均308帧/两线程。图优化/量化收益只是该小样本观察，不是普遍加速比例。
3. opt1前端与声纹分成两个面板：只前端显著下降，声纹变化约0.16%不作为显著收益。VAD和Mel已经包含在前端内，不能再叠加到总耗时上。
4. 同一输入CPU对照：独立前、前端并发、独立后，分别6次；保留第一次和离群值，不选择性剔除。
5. epoch26三窗时间/分数表：前两次3.806607/3.842636秒过期，最后1.755893秒但分数不足且发布已跨采集结束；不要把最后一次当持续并发速度。

图表不能把主机、QEMU与板端混在一起；不能把吞吐比当首个身份响应时间。首次响应还包括收集窗口、排队与判决。

## 必要失败事实

- [全网INT8未采用](records/E11/pc-evaluation.json)：历史真实块最低余弦0.98994076低于预设0.99数值条件。部分INT8也不等于无精度损失。
- epoch23小声录音被用户排除正常音量身份评价；只保留诊断用途。epoch22换人时刻不明，不做逐窗身份正确率统计。
- 原始target/non_target分数不是有效身份；结果过期或会话失败后不可用于控制。
- sha清单CRLF、Python环境、overlay路径和logs权限属于部署问题，不能当模型识别错误。
- FPR-R1发现“总Run数相符但某Run无节点仍COMPLETE”的统计漏洞；修正逐Run节点覆盖与归属，修复一次，见[E08复核](records/E08/review.json)。这属于测量质量改进，不是模型提速。
