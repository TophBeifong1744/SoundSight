# STM32 算法迁移到 Zynq：四人分工

2026-10-20。本目录仅存放本轮团队分工和共用接口说明，不存放源码、工程、运行报告或另一套任务数据库。正式 RTL、软件和工程配方继续使用仓库原有目录。

## 目标和方案

把 STM32 上的算法迁移到 Zynq PS，在不依赖 STM32 的情况下，完成真实声音采集、定位求解和转台控制闭环。

PL 保留采集、FFT/PHAT/IFFT、六对特征、快照缓存和 PWM 保护；PS 两个 ARM 核运行同一个 Linux/PYNQ 系统，由 Python 调用 C 求解器。不采用一核裸机、一核 Linux 的方案。

本文件记录本轮分工，不代表 B、C、D 已接单或成果已完成，也不改变原 STM32 方案的历史验证结论。公共接口见[接口表](接口表.md)，具体字段仍以既有公共头文件和当前实现为准。

Python 由 C 负责，C 求解库由 B 负责，PL 接口由 A 负责。D 不一边修改某项产品实现，一边把自己的判断称为该项独立复核。

复用已有代码和有效测试，不重新复制协议或算法。C 接续现有 `software/ps`，B 维护 `software/common/s1`，A 维护 `project` 中对应 PL+PS 内容；改动公共 RTL 时说明对 STM32 版的影响。

## 推进顺序

1. **算法迁移与 FPGA 准备并行。** B 用固定输入比较原算法与 Linux 版；C 用同一组数据接 Python 调用；D 独立核对预期。A 同时准备 PL+PS 工程。普通接口问题由对应成员直接接合，公共数值或停止语义需要改变时集中交 A 决定。
2. **板上取数与求解。** A 提供配套 bit/HWH；C 先跑 BIST，再接真实 PL 数据，完成“采集 → 六对数据 → 求解 → 保存”。D 核对真实结果和异常处理。此阶段不默认启用转台动作。
3. **闭环与持续运行。** 明确实际通道、几何、机械范围和看门狗参数后，由 A 执行现场动作，C 接通角度提交，B 分析算法结果，D 验证持续运行、STOP、恢复和故障处理。

做完必要自测直接交实际接收人，接收后及时接合；发现问题交对应负责人集中修复，不按收件、包装、小修改反复开确认轮次。一个工作副本同时只由一方修改；综合、实现、下载、复位及执行器动作由 A 执行。

## 完成标准与当前缺口

完成标准是同一套交付文件能够在目标板复现：真实采集、有效定位、结果保存、标定后的转台控制，以及停止和异常处理。编译成功、离线测试或某一版时序通过不能替代这个结果。

目前已有 C 求解器、Python 桥和 PS 接口可接续，但以下事项不能当作完成：

- 目标 ARM/PYNQ 实际运行和处理时延。
- Python 自动转台循环：当前 CLI 仅求解和保存，已有 arm/command 需由 C 接合。
- 实际通道、几何和机械标定，以及板上闭环验证。
- 长时间不取数时的行为：当前双槽保留旧帧、丢新帧并计数，不保证无损。发现异常后停止新增工作；若需要硬件自动满槽停采，应作为明确改动处理，不在文档里宣称已经实现。

保持现有数值、服务预算和 STOP 约定；不靠降低要求或延长超时掩盖问题。无需增加哈希、cookie、宽身份链或额外认证流程。
