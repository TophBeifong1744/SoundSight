按用户决定，从当前仓库删除独立源码、测试、音频示例、专属说明及提交副本，并清理混合资料中的对应条目。Git历史不重写，其他算法的原始数值和失败事实保留。完整运行包原本就未包含该模块，本次不改位流或在线采集/求解/控制逻辑。两份报告和海报由用户在各自聊天中另行修改，本次不改动在途成品。

## 2. 最终产品是什么

**SoundSight是基于Zynq-7020的本地三维声源感知与双轴指向系统，集成可选声纹许可和RGB触摸屏交互。** 主方案仅为PL＋PS/PYNQ；同一个双核Linux系统运行Python调度、C求解及声纹原生后端。

四项面向使用者的核心功能如下。音量门限、方向筛选、日志和保护是这些功能的配套能力，不重新凑成功能数量。

| 功能 | 输入、输出和实际用途 |
|---|---|
| 四麦三维声音定位 | 40mm正四面体四麦的同步音频及同区间快照，经CF1A前端和C几何求解，输出方位角、俯仰角及质量状态；估计方向，不测量声源距离 |
| 声纹录入与目标验证 | 录制一段语音，保存命名模板、选择目标；连续PCM进入语音检测和CP1/VF1推理，输出相似度分数及可配置时限许可；未配置目标/门限不给许可 |
| 水平/垂直双轴指向 | 支持无声音要求的手动标定、显式纯声音跟随、声纹许可跟随；轴可关闭、单独选择或双轴启用；零位、方向、范围可配置，保留STOP、超时和限位 |
| RGB触屏交互 | S2显示/触摸驱动与S3面板提供模式选择、轴选择、目标列表/选择、现有参数调整、状态显示和启停；一次仅一套采集所有者。录入新用户仍走现有终端命令，不声称已加入触屏录入按钮 |

辅助能力包括：可调音量门限、可调分组帧数和最低有效帧数、空间一致性筛选与3°死区、默认不开轴、普通运行的有界状态/结束摘要、调试模式及可选声纹累计次数和耗时统计、故障诊断与残留快照导出。

## 3. 组合关系与软硬件分工

```text
四麦同步采集（PL）
  ├─相关特征/定位快照、音量、音频区间信息 ─┐
  └─连续四路PCM → 单一DMA接收者（PS） ───┤
                                        ├─CF1A同区间前端 → C三维求解 → 方向筛选
                                        └─语音前端 → CP1/VF1 → 分数与TTL许可

触屏/终端选择模式与轴 + 合格方向 + 该模式所需许可
  → PS限位/映射和动作提交 → PL双轴PWM及停止/超时保护
```

PL继续承担同步采集、既有相关运算/快照、PCM导出和确定时序的执行器保护。PS的CF1A不是只读PL峰值的旧二维链：它利用同区间PCM做相位一致性前端，再调用C几何求解；滚动累加和有界历史补算保持既定数值判据。声纹分支处理原PCM，独立进程降低其计算对采集调度的影响。

声纹是**是否允许转动**的条件之一，不修改三维角度。纯声音模式明确绕过声纹条件，不能计为识别通过。手动模式独立于声音，但仍受机械范围、超时与停止保护约束。

现行`score_ttl_v2`：新评分达到门限后，从该次计算完成时间刷新有效期；计算下一轮、低分、静音或换段不自动延长，也不提前消除尚未过期的旧许可。到期且无新通过则失效；会话错误/真实故障仍停止。音量和当前方向质量独立限制动作，所以“许可还有效”不等于此时一定转动。

当前机制没有严格绑定“登记人的声音身份”和“多人混声中的某个空间方向”；不写成多人同时讲话时能精确锁定登记人。固定麦克风阵列不随舵机转，零位/安装方向/机械范围需要按实物配置。
