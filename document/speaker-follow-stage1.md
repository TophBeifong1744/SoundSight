# 声纹跟随第一阶段：单人发声识别与转向

记录日期：2026-10-23。状态：用户已确定第一阶段范围并采纳下述接口方向，尚未实施或验证。本次只更新并发布方案文档，不修改代码，不启动RTL、软件接入或硬件操作。接口语义和分阶段范围按本文执行；寄存器地址、逐字节包头布局、FIFO深度及实现预算在实施前补齐，不表示现有冻结ABI已经改变。

## 用户确定的目标

先通过FPGA连接的麦克风采集目标说话人的语音，建立其声纹模板。在同一时刻只有一个人说话、暂不加入多人同时混声的条件下，判断当前说话人是否为登记目标；确认是目标且方向有效时，控制转台朝其方向转动。

第一阶段登记一个目标。测试时允许目标与其他人轮流说话，用于验证系统能跟随目标并拒绝跟随非目标。只测试目标自己说话，不能证明身份区分有效。多人重叠、目标语音分离和多人轨迹关联留到后续阶段。

## 已采用的PL与PS/PYNQ分工

“FPGA采集声纹”在实现上拆成语音采集与声纹计算：PL采集的是语音波形，声纹是算法从语音中提取的特征。

| 位置 | 第一阶段职责 |
|---|---|
| PL | 四麦同步采集、PDM转PCM、现有定位特征计算；向PS提供音频及其采样范围；保留PWM及STOP等保护 |
| PL到PS | 连续四麦PCM经AXI DMA进入DDR；少量状态、控制和定位结果继续走寄存器；数据格式和缓存边界见下文 |
| PS/PYNQ | 音频缓存、目标登记、声纹提取与匹配、现有S1方向求解、身份和方向关联、目标角度提交 |
| 转台 | 使用已有水平轴控制路径与机械标定；本阶段不扩展双轴能力 |

第一阶段传输四麦连续PCM，但声纹模型明确选择其中一条通道；四麦仍用于定位。第一阶段不做波束形成或语音分离。登记和识别应尽量使用相同采集链及预处理，保留通道来源和统一采样时基，不能无说明地混合通道。四通道音频传输是本阶段必需项，为后续空间处理保留真实输入。

当前PS工程配方主要通过AXI寄存器读取定位特征，未配置连续PCM的AXI DMA通道；现有定位特征和音量字段不能替代声纹输入。新增音频传输是待实施事项，不能视为现有位流已经支持。

声纹计算先以PS软件为部署方向，不预先把整个模型搬入PL。现有原型只有电脑CPU运行记录，PS上的运行时兼容性、内存及延迟尚未验证。可先在电脑用FPGA采集的录音验证算法；这只算中间步骤，不算PL/PYNQ闭环完成。若PS性能不足，再提出模型简化或加速取舍。

## 两条工作流程

登记：目标单独说话 → FPGA采集PCM → 软件检查有效语音 → 提取声纹 → 保存目标模板。登记录音、开发校准录音和最终测试录音独立准备，不用同一录音反复测试证明识别效果。

运行：FPGA采集当前单人语音 → 软件判断目标／非目标／证据不足 → 关联同一话段的有效方向 → 检查结果年龄和现有动作条件 → 提交水平目标角度。

只有“目标身份成立、对应方向有效、结果未过期、现有保护允许”同时成立时才允许新转向命令。非目标、证据不足、静音、故障或过期结果不得触发新的跟随动作；静音和故障继续遵守现有STOP及撤输出规则，不额外承诺电机物理位置或保持力。

轮流说话也可能在一个较长识别窗口内包含两个人。测试初期应将话段隔开；集成时必须处理话段切换和旧结果失效，不能把上一人的身份继续套到下一人的方向上。音频与方向至少记录同一采集时基下的采样范围及结果年龄。现有VAD只检测语音活动，不保证检测说话人切换或多人重叠；本阶段靠受控场景限定单人输入，不能宣称已自动拒绝所有混声。

声纹确认与方向更新可以采用不同节奏，但身份只对已关联的有效话段成立。现有原型要求至少1.5秒有效语音，首次锁定还需叠加采集、传输和推理时间，不能承诺一开口即转向。实际窗口、有效期和延迟目标待录音及PS实测后确定。

## 接口总览与阶段划分

采用“连续音频、方向观测、声纹结果、跟随决策”四条独立数据接口，以同一采样时基关联。软件对象不是RTL端口清单；模型、模板、字符串、处理历史和后续轨迹字段只存在PS内存或日志中，不逐字段映射到PL寄存器。

```text
现有四麦PDM→PCM ─┬─ 现有分窗/FFT/相关运算 → 定位快照＋采样范围
                 └─ 新增有界FIFO/分包/DMA → PS连续四麦音频
PS：选通道/重采样/话段 → 声纹三态判断
PS：声纹结果＋对应方向＋时效/故障 → 跟随决策 → 现有水平动作路径
```

| 接口或能力 | 第一阶段必须实现 | 后续扩展预留，不在第一阶段实现 |
|---|---|---|
| `AudioFormat` / `AudioBlock` | 四通道连续PCM、格式声明、采样范围、缺口和异常、DMA所有权 | 更多通道、其他传输格式按版本扩展；不为其预建通道RAM |
| `DirectionObservation` | 现有单方向结果的PS包装；PL同帧采样范围；原角度/有效性语义 | 多方向观测列表、方向算法替换；不复制多套FFT或S1 |
| `SpeechSegment` | 原始单通道来源、原采样区间、VAD有效区间及音频引用 | 定向增强/分离来源、处理器版本及父音频引用 |
| `SpeakerResult` | 单目标、模板版本、三态/原因/分数、模型与阈值版本、输入引用 | 多目标候选结果；不预分配PL模板槽或声纹向量RAM |
| `FollowDecision` | 单目标关联、更新/撤销/不更新、有效期、现有动作保护 | 多声源轨迹关联与目标切换策略；不预建PL跟踪阵列 |
| 版本与能力 | 独立音频接口版本/当前能力；软件消息版本及未知能力拒绝 | 可选字段和新能力位，未实现能力为0，不占未用硬件存储 |

### 第一阶段必需：连续音频与采样时基

音频分支位于现有PDM转PCM之后、定位分窗之前。复用唯一四通道采集/CIC结果；当前1024点窗、512点步进的定位窗口存在重叠，不能首尾拼接成连续录音。音频块不重叠，每个真实采样只交付一次。

`AudioFormat` 在采集开始时读取并保持不变，包含 `sample_rate_hz`、`channel_ids`、`sample_format`、`valid_bits`、`layout`、`format_revision`。第一阶段通道顺序为mic0、mic1、mic2、mic3，按采样交错；传输为小端有符号32位，每个S24样本右对齐、符号扩展，不改变数值、不任意移位。固定四通道顺序由格式定义，不逐样本附带通道ID。

内部PCM/FIFO保持每通道24位，四通道共96位；只在DMA输出打包边界扩为32位字。32位是传输对齐格式，不要求所有RAM、跨域总线和运算都扩大到32位。PS转换浮点及16kHz时按已声明的有效位数和原采样率处理，不把声纹模型格式反向强加给现有定位链。

每个 `AudioBlock` 必须能恢复以下信息，紧凑包头与PCM在同一包中交付，不能另读实时寄存器猜测该块属性：

| 字段 | 语义及硬件位宽约束 |
|---|---|
| `capture_epoch` | 一次采集会话；PS完整会话标识＋硬件32位会话编号映射。编号在停采/排空后写入并确认，运行中不修改，不逐样本存储 |
| `block_seq` | 会话内32位块序号，用于重复/缺块检查；耗尽前停止并建立新会话，不静默回绕 |
| `sample_start` | 原始采样时基中的64位首采样编号；音频和定位共用唯一计数来源 |
| `sample_count` | 每通道采样数量，逻辑字段按无符号16位上限约束；实际上限同时受DMA长度和软件缓冲区限制。块内计数器仅取配置上限所需位数 |
| `flags` | 已定义的削顶、缺口、通道异常及结束状态，逻辑字段最多16位；内部仅实现实际使用位，保留位读0 |
| 包格式/长度 | 包头版本、头长度、有效载荷长度可正确解析和校验；不传动态字符串，不重复传整个流配置；具体偏移实施前定稿 |
| `payload` | 连续四通道PCM；字节数必须等于 `sample_count × 4 × 4`，与包长和DMA实际接收长度一致 |

`sample_count` 不包含包头，也不等于四通道数据字总数。`sample_end = sample_start + sample_count` 为排他上界，由PS计算，不在PL另存一份64位终点。定位窗口同样存首采样编号和必要长度；固定窗口长度可来自已确认配置。

每次四麦同步有效PCM使采样计数加一；会话起点在预热完成、共同启动边界定义为首个有效采样。计数在FIFO暂满或丢弃数据时仍反映真实采样经过的时间，不能只在DMA握手成功时增加。采样计数接近耗尽时停止，不静默回绕。硬件只需一个主计数器及块/窗口边界快照，不给每路麦、每对相关器各建计数器，也不每个样本携带64位编号。

重新采集、硬件复位或修改采样配置时建立新会话，丢弃上一会话的在途推理和关联。PS进程重新启动也不得把旧缓冲区解释成新会话；先确认停止、排空和启动边界。32位硬件编号不得在仍可能收到旧数据期间复用。多字寄存器读取使用一次锁定快照，不能分两次读取活动计数器而拼出不一致的64位值。

### 第一阶段必需：方向观测

`DirectionObservation` 在PS中包含 `observation_id`、`capture_epoch`、`sample_start/end`、`frame_sequence`、`valid/reason`、`azimuth_q8`、`coordinate_frame_id` 和可空的 `source_ref`。

现有S1数值、`angle_q8` 的单位和范围不改；阵列坐标与机械角度分开，零位/转向/限位仍由现有机械映射处理。第一阶段每个定位窗产生至多一个方向观测，不实现多峰/多目标算法。

新增定位采样元数据必须与原特征同帧锁定、同槽消费，并携带对应帧号供PS核对；不得读取新块的实时采样编号补给旧快照。优先使用PS侧扩展元数据区，不修改STM32冻结SPI字段、S1输入定义或现有寄存器含义。具体地址与一致性握手在实施前补齐。

### 第一阶段必需：话段、登记与声纹结果

`SpeechSegment` 在PS中包含 `segment_id`、采集会话、原始采样范围、VAD实际使用区间、音频引用和来源。第一阶段来源固定为 `kind=raw_channel` 加所选 `channel_id`。重采样及拼接VAD语音后仍保留到原始采样区间的映射，不能拿处理后数组下标匹配DOA。跨越丢样或会话边界的话段无效。

`SpeakerResult` 包含输入话段引用、`target_id`、`template_revision`、`selection_revision`、`model_revision`、`calibration_revision`、实际VAD区间、相似度、三态及原因。三态为 `MATCH`、`NON_MATCH`、`INCONCLUSIVE`；过短、未校准、音频缺口、推理失败等分别记录原因。相似度不是概率，跨模型不能直接比较。

登记/加载/选择目标由PS管理。更新模板或模型后重新验证校准适用性；切换目标时增加选择版本，使旧任务迟到结果失效。第一阶段只登记和选择一个目标，不需要预建多人模板检索结构。

声纹向量维数和模型内部张量不进入PL接口，192维仅是现有模型实现。`overlap_status` 软件字段允许 `UNKNOWN/SINGLE/OVERLAP`，第一阶段没有检测器时必须为 `UNKNOWN`；受控单人输入写入实验条件，不能冒充自动检测结论。

### 第一阶段必需：跟随决策与异步结果

`FollowDecision` 仅在PS中存在，包含 `decision_id`、`action`、`target_id`、声纹/方向引用、可空 `source_ref`、`azimuth_q8`、有效期和原因。`action` 区分 `UPDATE`（申请新角度）、`REVOKE`（撤销跟随许可）和 `NO_UPDATE`（本次无新角度）。`NO_UPDATE` 不延长旧许可；身份失效、到期或故障必须明确撤销。

模型不能直接写舵机寄存器。决策通过现有机械映射和动作接口，保留当前锁帧、许可、看门狗、BIST、STOP、故障及限位检查。接口扩展不授权绕过现有保护。

声纹计算不占用硬件快照槽等待：采集服务及时复制必要数据到有界PS缓冲并消费，推理异步进行。模型返回后先检查话段、会话、目标选择版本和采集年龄；真正提交时仍通过当前合格锁帧，并验证该帧与已确认目标的关联。当前方向有效不足以证明仍是同一个人，不能将旧身份配给任意新帧，也不能伪造锁帧号重放旧帧命令。

第一阶段以受控单人、分开话段、有限有效期及不确定时重新确认为边界；若无法证明仍属同一话段/声源，就不发新命令。已有VAD不保证检测无停顿换人，不能把本阶段写成无限持续锁定。有效期基于采集时刻，结合PS单调时钟和采样进度锚点检查；使用保守年龄上界，不能用推理完成时间或DMA到达时间冒充采样时刻。采集停滞时也必须能使旧结果过期。

### 第一阶段必需：控制、缓存所有权与异常

音频控制采用独立版本/能力区或独立IP，最小包含版本、已实现能力、格式/块大小、会话编号、启动/停止、运行/排空/故障状态、丢样诊断及采样进度快照。精确地址和DMA配置尚待定稿，不提前占用冻结协议中的保留位。运行中禁止改格式；不支持的必需版本或能力明确拒绝。

DMA缓冲区按 `FREE → DMA_OWNED → CPU_READY → FREE` 管理，只有完成和缓存同步后CPU才可读取，仍被DMA或软件引用时不得重用。第一版允许复制到有界话段缓存以尽快归还DMA块，不为零拷贝增加复杂共享所有权。停止时先撤动作许可、停止新增并完成/取消在途传输，确认DMA不再写入后才释放缓冲；不能超时后直接释放仍在写入的内存。

队列和FIFO均有容量上限。PL FIFO只吸收有限传输抖动，不等待模型完成；音频分支不得反压停止物理PDM时钟或拖住原定位链。无法接收时显式丢弃并报告缺口，半包不可当完整块消费；下一块采样编号应反映缺失区间，流若已停止则由停止/故障记录说明尾部缺口。缺口导致受影响话段及身份关联失效并撤销跟随，不能补零假装连续。定位分支原有故障规则保持。

推理任务队列满时可取消过期任务，记录原因；不丢弃仍在使用的底层音频引用。拒判、超时和推理异常都保留原因，不改写成非目标识别成功。

### 后续扩展预留：仅保留软件语义和版本入口

后续 `SpeechSegment.source` 可新增 `beamformed/separated`、父音频引用、处理器版本与声源引用；方向接口可返回多条观测；跟随层可新增 `track_id` 及多目标候选。`track_id` 表示声源轨迹，不等于登记身份；时间重叠或分离输出序号相同，都不足以证明身份关联。

第一阶段只支持 `raw_channel` 路径、一个目标及一个方向，`source_ref/track_id` 无可靠值时为空，不用永久的“0号目标”伪装已经跟踪。未来扩展字段放PS，不预留宽RTL总线、空BRAM表、多路运算核、波束权重RAM、模型权重RAM或硬件哈希链。

软件消息与硬件音频接口独立版本化：兼容的可选字段可追加，改变必需字段含义、单位、包布局或握手语义时升级相应主版本；未知可选字段可忽略，未知必需能力必须拒绝。新增硬件能力另按实际需求实现，不能从预留字段推导已经支持。

## PL位宽、资源、时序和逻辑复用约束

用户要求：避免无用途位宽、资源/布线拥堵和重复逻辑。下列是实施约束，不是已达到的资源或STA结果。

1. **一次采集、多路使用。** 复用现有PDM/CIC、定位分窗、FFT/相关器、S1及PWM保护，不为声纹另造第二套相同逻辑。只增加必要音频支路、分包/传输、边界元数据及一致性控制。声纹VAD、重采样、Fbank和网络先在PS运行。
2. **精度与存储分开。** 保留S24有效音频，不为省资源随意截成16位。PL样本存储按96位四麦数据和必要异常位预算，32位符号扩展放在传输边界。常量格式保存在配置中，块头元数据每块一次，定位元数据每窗一次，不逐样本携带身份、版本和时间终点。
3. **按范围决定计数位宽。** FIFO指针、通道索引和块内计数用配置范围所需位数，避免通用32/64位计数器到处复制。唯一64位采样计数及必要快照保留其完整语义；如进位路径成为关键路径，可按等价时序分段实现，但必须保持边界快照正确。不能缩窄后依赖PS轮询碰运气补回绕。
4. **DDR承担长缓存。** 秒级话段和模型输入放PS DDR，PL仅留有预算的短FIFO。物理BRAM数量按深度、端口及打包粒度核算，不能只按理论字节数宣称一定节省。以48kHz、四通道为预算示例：S24原始负载576,000 B/s，S32 DMA负载768,000 B/s，另加包头；512组S24理论数据量6,144 B，传输载荷8,192 B。示例不是冻结块大小或板测带宽。
5. **窄通道分拍传输。** 优先用32位流按通道串行打包，避免将完整块头、四麦数据和所有软件元数据组成超宽组合总线。FIFO深度应覆盖实测DMA重新提交/调度抖动，长期传输服务能力必须高于输入速率；不以低平均带宽推导Linux调度一定不丢样，也不盲目加深FIFO掩盖问题。
6. **显式流水及跨域。** 保留现有61.44MHz采集域和100MHz计算/AXI域；使用官方FIFO/CDC与复位方案传递数据及边界元数据，确保原子对应。避免跨模块长组合ready链、高扇出全局比较和宽选择器；包头序列化、长度计算和状态判断安排寄存边界。静态配置在停采时握手更新，不对多位总线逐位同步后直接拼接。
7. **复用不能制造争用。** 利用既有IP/存储前先确认端口、时隙和吞吐余量；不能为了“复用”让音频读取长期占住定位窗口RAM，也不能未经调度预算就把新功能塞入已有FFT时序。若确有必要的小型寄存器/FIFO隔离，可在预算中说明其用途。
8. **实际报告决定是否收敛。** 实施前列出增量与整机LUT/FF/BRAM/DSP、FIFO深度、DMA块/带宽、PS内存和最坏服务间隔预算；后续由用户运行综合/实现取得同候选利用率、拥堵、setup/hold及CDC/RDC证据。不能靠放宽时钟、错误false-path/multicycle或删除保护通过。本文不设未经报告支持的资源余量百分比，不声称已有时序闭合。

实现前还需定稿：紧凑包头布局与最大块长、扩展寄存器地址和能力位、采集会话启动/排空握手、FIFO/PS队列深度、DMA驱动及长度配置、身份有效期和动作延迟目标。上述取值不改变已采用的接口分层；若影响公共合同、采样精度、时钟或目标范围，则另行提交技术取舍。
