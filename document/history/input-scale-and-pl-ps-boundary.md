## 1. 本次确认结论

1. **H1 交换标度与已有 B 适配器一致**：24 位有符号 PCM 码值，int32 右对齐，符号扩展；浮点输入为 `pcm / 2^23`，不是按录音峰值或每通道独立归一化。
2. **当前实际 one 工程仍是另一种输入**：`one-test-source-v1` 四通道 signed16 数字码型，32 位 AXI 流、每组 3 拍；不是 H1 的二进制形式，也不是真实 PCM 采集。
3. **实际 PDM→PCM 标度尚未冻结**：未找到该 BD 中的 PDM 接收/抽取模块；滤波器、总增益、输出移位、舍入、饱和和真实精度仍须实际实现与验证。48 kHz 与 24 位不能作为已实测事实。
4. **部署分工沿用现行架构**：PL 承担确定性实时声学数据面，PS/PYNQ 负责控制、记录与导出。离线 Python 实现不是部署到 PS 的决定。

### 当前 signed16 码型与 H1 的关系

测试源中的 16 位补码必须先按 signed16 解码；不能把 0xFFFF 当正数65535。若未来需要导出 H1 **诊断码型**，保持码值的候选转换为符号扩展至 int32，不自动左移8位。此时 -32768→-32768→H1浮点 -1/256，32767→32767/8388608。它不等于 signed16 满量程归一化的 [-1,1)，也不是真实录音。

该转换只是桥接候选，本次没有实现或验证导出器；若选择左移等另一策略，必须另行版本化并由 B 确认，不能无声混用。32位测试编号每次 start 归零且可能回绕，不能简单转换类型后冒充持续 uint64 采集；导出需明确新 acquisition_id、重启及回绕处理。测试源没有提供完整 H1 错误语义，不得擅填“链路无错误”。

### 六麦研究 profile 不与 H1 混用

本轮六麦浮点研究继续使用 `six-mic-baseline-synthetic-v1`。六路浮点合成值没有固定 PCM 满量程保证，不能直接称为 signed24；B 做六麦定点候选时必须显式指定统一缩放、峰值/溢出处理及相应 golden，保留合成来源。不修改已归档研究输入，不把六路数据塞入四路 H1 schema，也不新增四麦声学模拟。

PYNQ 是首选控制后端，板级镜像/Overlay/导出路径仍需 M0 验证；必要时使用 Vitis 裸机或 PetaLinux，但不得改变寄存器/DMA合同。实时 PL 不依赖 Python 运行时；PS 停顿/退出时按冻结的缓冲与安全策略处理，不能让不可暂停的物理采集随之停钟。

## 5. B 现在可开展的工作与共同冻结条件

**B 可立即开展**：沿用上面已实现的 H1 固定标度，另外为六麦合成 profile 明确候选缩放；提交每级最大幅值、候选位宽/小数位、舍入/饱和、PHAT低能量保护、FFT需求及每帧运算/缓存预算。生成零、正负端点、近满量程、低能量和溢出向量，开展参数化量化研究。固定点候选模型不等于已与最终 IP 位精确一致。

**A 后续补证据**：真实 PDM/抽取实现及输出映射、实测采样率/通道映射、抓取点和编号/错误生成；提供 FFT IP 实际配置及与位宽相符的预算。现有 FCLK0=100 MHz 仅可作为候选预算输入，不能提前承诺声学核心满足该时钟。

**联合冻结最小输入**：采集链与配置身份、PCM增益/标度、帧长/步长/窗、FFT架构及各级缩放、各级格式/舍入/溢出策略、PL状态机语义、配置生效帧边界、缓存与时间预算。B 提出需求和数值依据，A 核查工程可实现性；不要求 B 等最终实板时序报告才做准备，但未冻结不能宣称最终位精确验收通过。

本版结论只确认现有软件标度及目标职责。实际 PCM 标度缺口保持待验证，不把“确认表填写完成”当作硬件参数全部冻结或 H1 双方补签。
